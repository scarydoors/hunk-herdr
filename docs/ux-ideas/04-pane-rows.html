Richer Threads pane rows

A group with a bound agent looks identical to one without. A comment the agent has replied to looks identical to one it hasn’t. And after assigning a comment the pane opens with nothing selected. All three answers already exist in extension state; the pane just doesn’t draw them.

Where the data comes from

Agent on the row

threadAgents lives in index.ts, the pane store in threads-pane.tsx. Mirror the binding into the store when it changes: setThreadAgent(threadId, { label, owned }) on choose / stop / retire. The pane never talks to Herdr.

Reply counts

note_changed fires for agent session comments with source: "agent" and parentId. On created/removed, if the root is an assigned comment, adjust replies. Seed from ctx.review.snapshot() on changeset_loaded so a reload doesn’t drop counts.

Select on assign

assignComment/createThread return the thread; set selectedKey = thread:<id> there so Ctrl+T then P is immediate. 01 depends on this for its toast flow but it’s useful on its own.

Width budget

The pane is 28–72 columns. oneLine() already truncates; put the suffixes outside the truncated span so · claude and · 1 reply survive when the title is long. At the 28-column minimum, drop the agent label before the count.
