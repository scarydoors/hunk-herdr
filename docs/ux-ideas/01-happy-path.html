Shorten the happy path

From “I saved a comment” to “an agent is working on it” took up to seven modal interactions. Every one of them was a gate the extension added; none is required by Hunk or Herdr. Removing them turns the flow into comment → Ctrl+T → P → Enter → Enter. The Threads sidebar is the cursor for comments: moving through it reveals each comment in the diff, and every action runs from the selected row.

Revision · the sidebar drives the diff, not the other way round

The first version tried to make P, A and Ctrl+R act on the comment under the review cursor and to have the pane highlight it. Hunk exposes no active-note signal, reports no current line on a note row, and paints no current line for panes in the unified layout, so this needed a replayed model of Hunk’s cursor that broke on hunk jumps and folds. That code is gone. Instead the sidebar selection reveals the comment in the diff through revealLine, which Hunk does exactly, and P, A, Ctrl+R and X act on the selected row. Ctrl+T lands on the comment saved last, so the happy path costs one extra key. Recorded run: sidebar.gif (asciinema cast).

a · Every comment lands near its neighbours

No dialog. A saved root comment joins the group that already holds the closest comment in the same file; when the file has none, it goes to Unassigned. Naming or splitting is the exception, done after the fact with Ctrl+R.

// index.ts · assignUserComment
 on(note_created, note)
   if note.draft or note.parentId: return
-  picked = dialogs.select("Assign saved comment to a thread", …)
-  … create / choose / Unassigned branches …
+  nearest = nearestThreadForNote(note)     // same file, min |line − comment.line|
+  thread  = nearest ? assignComment(nearest.id, note) : assignUnassignedThread(note)
+  panes.open("threads")
+  notify `Added to ${thread.title} · Ctrl+R to move or name`

Where named threads come from

Ctrl+R on a comment or group: Unassigned · another thread · + Create new thread…. It works from Threads navigation and, with b, from the review cursor too, so “name the comment I just wrote” is Ctrl+R, type, Enter.

b · The sidebar is the cursor for comments

While Threads navigation is focused, moving the selection onto a comment reveals it in the diff, so j/k walk the review comment by comment across hunks and files. P, A, Ctrl+R and X take the selected row. Pressed from the review, they show one notice: Focus Threads (Ctrl+T) and select a group or comment first. Ctrl+T lands on the comment saved last.

// threads-pane.tsx · ThreadsPane
 selection = selectedThreadItem()
+useEffect(() => {
+  if (navigating && selection.kind == "comment")
+    actions.revealLine(file.id, anchor.side, anchor.line)   // Hunk's live anchor, else the saved one
+}, [selection.comment.id])

// index.ts · resolveThreadSelection(ctx)
-shown = pane highlight ?? threadAtSelection(snapshot, ctx.selection, replayedCursor…)
+if !keyboardModes.isActive("threads"): notify "Focus Threads (Ctrl+T) …"; return
+return selectedThreadItem()

After the file changes

Verified live: Hunk does not re-anchor a note when its file is edited. Inserting three lines above a comment on new line 12 left the note at new line 12, still reported active, now sitting on different content; a note whose hunk disappears stops rendering. The sidebar’s reveal therefore lands exactly where Hunk shows the note. Each Threads command, Ctrl+T first, reads ctx.review.snapshot() for current anchors and shows any verdict Hunk reports (● stale, ✗ gone). A watch reload cannot be read live: it emits no note event and event handlers have no snapshot, so those marks update on the next key.

Why not the review cursor

Hunk’s selection reports no current line while the cursor rests on a note row, never names the active note, and in the unified layout paints no current line for panes at all. Following it meant rebuilding Hunk’s stop list and replaying reported commands; stepping across a fold into another hunk desynchronised it. The exact fix would be upstream (an activeNoteId on the extension selection). Until then the sidebar owns the selection and Hunk owns the reveal.

e · Two small gates in the same spirit

Ctrl+L doesn’t need Threads focus

configureModels refused unless the mode was active, but never read the selection. The check is gone.

Clear the draft on submission, not completion

drafts.delete ran after the agent’s turn ended, so P mid-turn pre-filled text you had already sent. It is now cleared when the prompt is handed to Herdr and restored only if that hand-off fails.

f · What the pane shows

The selected comment is marked with › in the accent colour and the diff is scrolled to it; the group heading toggles with Enter. There is no second “active” highlight: one selection, one meaning.
