Persist threads and reattach agents

Groups, titles, assignments and agent bindings vanish when Hunk exits; temporary hunk-… agents are closed best-effort and otherwise orphaned. Nobody invests in grouping state that dies with the window. The extension already owns a state directory for model defaults — threads belong there too.

Store comment IDs, not comment contents — Hunk’s ReviewStore owns bodies and anchors, and ctx.review.snapshot() rehydrates them. A comment ID that no longer exists in the snapshot is dropped silently; a group left empty is retired, exactly as retireEmptyGroup does today.

Startup: rehydrate + reattach

on(startup | changeset_loaded)
  file = threads/<hash(cwd)>.json
  if none: return                                        # first run, nothing to do
  snapshot = ctx.review.snapshot()
  for group in file.threads
    comments = group.comments ∩ snapshot.notes(source:"user", active)
    if empty: skip                                       # resolved while Hunk was closed
    publish group with comments
    if group.agent
      live = herdr agent list → find(pane_id, terminal_id, name)
      if live:      bind(group, live)                    # same identity check as Bridge.validate
      elif owned:   mark attention "agent gone"          # pane closed or Herdr restarted
  if any owned agent could not be found
    notify "1 temporary agent from last session is gone" # nothing to clean up

on(every publish)                                        # debounce 250 ms
  write file atomically                                  # same tmp+rename as saveModelDefaults

on(shutdown)
  write file
-  stop every owned agent
+  leave owned agents running; they are reattached next time

Two decisions to make

Do temporary agents survive Hunk?

Today shutdown closes them. If they persist, the zoom that hides them is gone too — the next Hunk launch should re-zoom if an owned agent is found. Alternative: keep closing them on graceful exit and only persist the grouping. That is the smaller first step and still fixes the orphan problem, because a crash-orphaned agent is at least recognised and offered for cleanup on the next start.

Key by repo root or by review?

Comment IDs are stable per Hunk session store, which is per repo. One file per repo root is the natural unit; a worktree is its own root and its own file. Keying by branch would split state a user considers one review.
