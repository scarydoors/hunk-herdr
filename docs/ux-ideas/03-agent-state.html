UX ideas · 03

Make agent state visible

Temporary agents live in a pane hidden by zoom. Claude’s trust prompt, a login, a permission request — all happen where nobody is looking. Today that ends as a warning toast that fades and a spinner that simply disappears. The group row needs a third, sticky state, and completion should reach the user even when they’ve switched panes.

Group-row states

Today · 3 states, one transient

 ▾   Authentication (2)            idle — no agent, or agent bound
 ▾ ⠋ Authentication (2)            starting / sending / turn running
 ▾ ✓ Authentication (2)            last turn settled idle|done
 ▾   Authentication (2)            blocked → spinner cleared, toast faded

Proposed · 4 states, all persistent

 ▾   Authentication (2)
 ▾ ⠋ Authentication (2) · claude
 ▾ ✓ Authentication (2) · claude
 ▾ ! Authentication (2) · claude · needs attention — A to reveal

State machine

                 P / choose
   idle ──────────────────────▶ dispatching ⠋
    ▲                              │
    │ new prompt                   │ Herdr `agent wait` returns
    │                              ▼
    │            ┌── status idle|done ──▶ completed ✓ ──┐
    │            │                                      │ P again
    └────────────┤                                      ◀┘
                 │
                 └── status blocked,                    ┌─ A → Reveal, or
                     `agent_prompt_stalled`,   ──▶ ! ───┤  P again, or
                     spawn error                        └─ resolve group   ──▶ idle

Reach the user when they’ve left the pane

Hunk toasts only show inside Hunk. Herdr has its own notification surface, and the extension is already shelling out to herdr.

// bridge.ts
+async notify(title, body, sound: "done" | "request" | "none") {
+  await this.api(["notification", "show", title, "--body", body, "--sound", sound])
+}

// index.ts · watchDispatch
 on settled → bridge.notify("Hunk · Authentication", "claude finished", "done")
 on blocked → bridge.notify("Hunk · Authentication", "claude needs attention", "request")

Config flag

notifications = "herdr" | "hunk" | "both" in [extension.hunk-herdr], default both. Some users will find the double signal noisy; the Hunk toast remains the baseline.

Remove the dead badge()

index.ts keeps a no-op badge(_ctx, _message) and the README claims status-row support is feature-detected. Neither is true at runtime. Either implement it — (ctx as any).statusLine?.set({ id: "herdr", text }) works on API 28 hosts and is a safe no-op on 0.22.0 declarations — or delete the stub and the README line. The pane row is the better home for this state anyway, so deleting is the recommendation.
