UX ideas · 02

Pass the session, don’t make the agent find it

The prompt tells the agent to run hunk session list --json and to ask if several sessions match. The agent is hidden behind Hunk’s zoom, so a question is invisible — the user sees a spinner that never ends. The extension already knows the exact session: removeThread() resolves it by reviewPublication.generation before every resolve.

Failure mode today

P → prompt sent
→
agent: hunk session list
→
2 sessions match cwd
(two Hunk windows, or a worktree)
→
agent asks “which one?”
in a pane nobody can see
→
⠋ spins until resolve/stop

The spinner is honest — Herdr’s wait matches idle|done|blocked, and an agent waiting for an answer is idle only if its CLI reports it that way. Either way the user has no idea a question was asked.

Proposed

P
→
extension: hunk session list --json
match generation — same code as resolve
→
prompt carries sessionId
→
agent uses it verbatim

Where the ID comes from

// threads.ts — extract from removeThread, reuse in both places
+export async function liveSessionId(run, cwd, generation): Promise<string> {
+  listed = JSON.parse(await run("hunk", ["session", "list", "--json"], cwd))
+  matches = listed.sessions.filter(s => s.snapshot?.state?.reviewPublication?.generation === generation)
+  if matches.length !== 1: throw "The live Hunk session could not be identified"
+  return matches[0].sessionId
+}

Side effects worth noting

Failure moves to the user

If the session can’t be identified, P now fails with a warning toast before anything is sent — the same message resolve already shows — instead of the agent stalling.

One fewer agent tool call

The agent skips session list and goes straight to session review, so the first visible progress arrives sooner.

Independent of every other idea

Touches buildPrompt, one helper in threads.ts, and the prompt test fixtures. No pane or state changes.
